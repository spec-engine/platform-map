SHAPE 3 — THE POINT A platform of separate repos Repos that share no git history become one map. A small checked-in definition names the platform and its members; each member carries a two-line marker so it knows where it belongs. Anything unexpected is reported, never guessed.
On disk — the acme platform folder
acme/ ├─ .git/ ├─ platform-map.json ← the definition (checked in) ├─ svc-api/ a plain repo │ ├─ .git/ │ ├─ package.json │ └─ platform-map.json ← member marker ├─ web-mono/ a whole monorepo │ ├─ .git/ │ ├─ pnpm-workspace.yaml │ ├─ platform-map.json ← member marker │ └─ packages/ ui/ site/ ├─ scratch-experiment/ a repo NOBODY declared └─ docs/ not a repo at all
acme/platform-map.json — the definition
{ "name": "acme",
  "members": [ { "name": "svc-api" },
               { "name": "web-mono" } ] }
acme/svc-api/platform-map.json — the marker
{ "platform": "acme", "root": ".." }
What platform-map sees
acme · mode: multi-repo
svc-api repo app
web-mono repo · monorepo
packages/ui library
packages/site app
packages/site ──▶ packages/ui
UNCONFIGURED_SIBLINGscratch-experiment has a .git but nobody listed it — flagged as a candidate, never silently added as a member.
PLATFORM_DRIFTdocs/ sits at the platform root but is neither a repo nor a member — noted, not guessed.
PROOF ✓Run it at acme/ or from deep inside web-mono/packages/site/ — the JSON output is byte-identical. Same map from anywhere in the platform.
BOOTSTRAP Where do those config files come from? platform-map init writes them On a fresh copy of the same folder with zero config, one command proposed and wrote the definition plus one marker per repo it found — and the folder immediately mapped as a platform. It lists every file first and never overwrites anything.
One command
$ platform-map init --yes acme-fresh/ files written: acme-fresh/platform-map.json acme-fresh/svc-api/platform-map.json acme-fresh/web-mono/platform-map.json acme-fresh/scratch-experiment/platform-map.json
Immediately after
acme-fresh · mode: multi-repo · 3 members
Every .git child it found was proposed as a member — the confirm prompt (without --yes) is where you'd leave scratch-experiment out.
HONESTY Drift is flagged. Your local folder layout is invisible. Two guarantees that make the map trustworthy for a whole team.
A marker pointing at the wrong platform
driftco/svc-drift/ └─ platform-map.json { "platform": "other" } ← names the wrong platform
PLATFORM_DRIFTmember svc-drift marker names "other" but the definition names "driftco" — a warning, never a silent guess.
A member moved somewhere else on your machine
plat/ ├─ platform-map.local.json ← yours, never committed │ { "locations": { "svc-good": "../_relocated/svc-good" } } └─ svc-good/ is gone — it lives in _relocated/ now
MATCHThe map is byte-identical with and without the local file. Your disk layout never leaks into the shared output.
